# 🏊 SWIM-AI — پلتفرم تحلیل هوشمند بیومکانیک شنا

دموکراتیزه‌کردن تحلیل بیومکانیک سطح آزمایشگاهی، فقط با یک ویدیوی معمولی گوشی:
تشخیص خودکار سبک شنا، شناسایی خطاهای تکنیکی، محاسبه سرعت/SWOLF/نرخ ضربه و
ارائه گزارش تصویری و نمودارهای تعاملی.

## اپلیکیشن دسکتاپ (PySide6 + OpenGL + pyqtgraph)

رابط کاربری فریم‌لس با تم تیره اقیانوسی، کاملاً راست‌به‌چپ و فارسی:

- **پس‌زمینه متحرک استخر با OpenGL واقعی (GLSL 330 core):** گرادیان اعماق،
  کاستیک‌های نور، پرتوهای نور و حباب‌های بالارونده. در صورت نبود بستر OpenGL،
  به‌صورت خودکار نسخه نرم‌افزاری QPainter جایگزین می‌شود.
- **صفحه خانه:** انتخاب ویدیو با دکمه یا کشیدن‌ورها کردن (Drag & Drop)،
  پیش‌نمایش فریم اول و تنظیمات تحلیل (قد، طول استخر، زاویه دوربین، FOV، مدل Pose).
- **صفحه تحلیل:** استپر شش‌مرحله‌ای زنده، نوار پیشرفت فریم‌به‌فریم، کنسول لاگ،
  دکمه **توقف تحلیل** (لغو همکارانه بین فریم‌ها)، پخش‌کننده ویدیو با overlay اسکلت
  رنگی (سبز/زرد/قرمز) و انتخاب ویدیوی HUD.
- **صفحه نمودارها:** ۱۰ نمودار تعاملی شامل سرعت لحظه‌ای، SPM، زاویه آرنج/زانو،
  Roll/Pitch، SWOLF دومحوره، طول ضربه، تقارن، رخدادهای بحرانی و رادار سبک‌ها.
- **صفحه گزارش:** ۱۰ شاخص کلیدی، نوار توزیع وضعیت تکنیک، رخدادهای بحرانی و
  **پیشنهادهای هوشمند مربی‌گری همراه با تمرین اصلاحی (Drill)**، به‌علاوه دکمه
  باز کردن خروجی JSON/ویدیو.
- **پرونده شناگر + گزارش PDF:** فرم مشخصات شناگر (نام، تاریخ شمسی، باشگاه، مربی،
  رویداد، سطح، جلسه، قد، یادداشت) که در سرصفحهٔ گزارش چاپی می‌آید و دو خروجی
  **PDF رنگی** و **PDF سیاه‌وسفید** مخصوص چاپ A4 می‌سازد.
- **پنجرهٔ «درباره نرم‌افزار»:** در نخستین اجرا خودکار باز می‌شود (با تیک
  «دیگر نمایش نده» در گوشهٔ پایین‌راست) و شامل هدف برنامه، سازنده، حق انحصاری و
  سال ساخت است؛ بعداً از دکمهٔ ⓘ در نوار عنوان یا سایدبار هم باز می‌شود.
- **موزیک کوتاه شروع:** یک قطعهٔ ۲.۵ ثانیه‌ای با تم آب/استخر (حباب، پاشش آب و سه
  نُت زنگ) که با `winsound` ویندوز پخش می‌شود؛ کلید 🔈 در نوار عنوان آن را
  خاموش/روشن می‌کند.
- **نوتیفیکیشن (Toast):** هر دکمه و رویداد مهم (انتخاب ویدیو، شروع/پایان/خطای
  تحلیل، ذخیرهٔ پرونده، ساخت PDF، تغییر صفحه) یک نوتیف کوتاه در گوشهٔ پایین‌راست
  نشان می‌دهد.

نوار عنوان: **نام برنامه در سمت چپ** و **دکمه‌های کوچک‌کردن/بزرگ‌کردن/بستن در
سمت راست**؛ متن‌های داشبورد و سایدبار راست‌چین هستند.

پایپلاین تحلیل در یک `QThread` جدا اجرا می‌شود تا رابط کاربری همیشه روان بماند.

## نصب و اجرا

### 🪟 ویندوز — ساده‌ترین روش (دابل‌کلیک)

| فایل | کاربرد |
|---|---|
| **`run.bat`** | اجرای عادی با پس‌زمینه متحرک OpenGL |
| **`run_debug.bat`** | حالت امن (رندر نرم‌افزاری بدون OpenGL)؛ اگر پنجره باز و بسته شد، با این فایل اجرا کنید |

هر دو فایل **خودکفا** هستند: بار اول `.venv` می‌سازند، کتابخانه‌ها را نصب
می‌کنند و سپس برنامه را اجرا می‌کنند. `run_debug.bat` در واقع همان `run.bat`
است با آرگومان `--safe` که درایور گرافیک را دور می‌زند.

فقط فایل **`run.bat`** را دابل‌کلیک کنید. بار اول به‌صورت خودکار:

1. پایتون پیش‌فرض شما را اگر در بازه **3.10 تا 3.14** باشد استفاده می‌کند،
   وگرنه با لانچر `py` سراغ نسخه‌های نصب‌شده سازگار می‌رود،
2. یک محیط مجازی `.venv` می‌سازد (اگر `.venv` قدیمی با پایتون ناسازگار ساخته
   شده باشد خودکار بازسازی‌اش می‌کند)،
3. همه کتابخانه‌های `requirements.txt` نصب می‌شوند (چند دقیقه طول می‌کشد)،
4. برنامه اجرا می‌شود. دفعات بعدی فقط پنجره برنامه باز می‌شود.

> ✅ **پایتون ۳.۱۰ تا ۳.۱۴ پشتیبانی می‌شود.** برنامه بک‌اند دوگانه دارد:
> روی مدیاپایپ جدید (۱.x) از **PoseLandmarker Tasks API** استفاده می‌کند که
> وییل عمومی `py3-none` دارد و روی پایتون ۳.۱۳/۳.۱۴ هم نصب می‌شود؛ روی
> مدیاپایپ قدیمی (0.10.x) همان API کلاسیک به‌کار می‌رود. مدل‌های `.task`
> داخل پوشه `models/` همراه پروژه ارائه شده‌اند (در نبودشان دانلود خودکار).

### 🐧 لینوکس / 🍎 مک

```bash
chmod +x run.sh
./run.sh
```

### نصب دستی

```bash
python -m venv .venv
# ویندوز: .venv\Scripts\activate   |   لینوکس/مک: source .venv/bin/activate
pip install -r requirements.txt
python run.py
```

اجرای نسخه خط فرمان (بدون رابط):

```bash
python swim_ai.py video.mp4 -o out.mp4 --json out.json --height 1.80
```

## 📦 ساخت نسخه نصب‌شدنی برای ویندوز

اگر می‌خواهید برنامه را روی کامپیوتری **بدون پایتون** اجرا کنید:

1. `packaging\build_windows.bat` را دابل‌کلیک کنید →
   خروجی `dist\SWIM-AI\SWIM-AI.exe` (پوشه قابل کپی، ~۳۵۰ مگابایت).
2. برای یک فایل نصب تک‌فایلی، [Inno Setup 6](https://jrsoftware.org/isdl.php)
   را نصب و همان فایل را دوباره اجرا کنید →
   `dist\SWIM-AI-Setup.exe` (~۱۵۰ تا ۲۰۰ مگابایت).

راهنمای گام‌به‌گام و جدول کامل حجم‌ها: [`docs/build_windows_fa.md`](docs/build_windows_fa.md).

> `.venv` پوشه **توسعه** است و حدود ۶۶۵ مگابایت (پس از بهینه‌سازی) حجم دارد؛
> نه لازم است کپی شود و نه در فایل نصب می‌آید. دلیل حجم کم شدن: جایگزینی
> `PySide6` کامل با `PySide6-Essentials` (۶۷۲ → ۲۴۵ مگابایت) و حذف کامل
> `scipy` (۱۴۳ مگابایت) به‌نفع پیاده‌سازی NumPy از `find_peaks`.

## 🆘 عیب‌یابی: «پنجره باز می‌شود و سریع بسته می‌شود»

> ✅ **از این نسخه به بعد، معمولاً هیچ دستوری لازم نیست.**
> فقط روی **`run.bat`** دابل‌کلیک کنید. لانچر جدید:
> 1. اگر پوشه `.venv` پروژه از قبل ساخته شده باشد، **همان را استفاده می‌کند** —
>    حتی اگر `python` سیستم شما ۳.۱۵ یا جدیدتر باشد؛
> 2. اگر `.venv` نباشد، با اولین پایتون سازگار (۳.۱۰ تا ۳.۱۴) خودش می‌سازد و
>    کتابخانه‌ها را نصب می‌کند؛
> 3. اگر هیچ پایتون سازگاری روی سیستم نبود، پیام فارسی با **دستور دقیق نصب**
>    نشان می‌دهد و پنجره را باز نگه می‌دارد.
>
> همین رفتار برای `python run.py` هم پیاده شده است: اگر با پایتونِ سیستم
> (بدون کتابخانه‌ها) اجرایش کنید، خودش به محیط پروژه منتقل می‌شود.
> اگر باز هم مشکلی بود، این را اجرا کنید تا وضعیت محیط مشخص شود:
>
> ```bat
> doctor.py
> ```
> (روی ویندوز می‌توانید روی `doctor.py` دابل‌کلیک هم بکنید.)

### ۰) اگر `git` نصب نیست

هیچ نیازی به `git` ندارید. لانچر (`run.bat`) و کد برنامه بدون git هم اجرا
می‌شوند؛ فقط کافی است فایل‌های جدید همین پوشه را داشته باشید.

### ۱) نسخه پایتون شما ۳.۱۵ یا جدیدتر است

برنامه با **Python 3.10 تا 3.14** کار می‌کند؛ برای ۳.۱۵ هنوز بسته آماده‌ی
`mediapipe` و `PySide6` منتشر نشده است. **توصیه: Python 3.12.**
اگر `.venv` پروژه را یک بار با ۳.۱۲ ساخته باشید، دیگر نیازی به نصب دوباره نیست
و `run.bat` همان محیط را استفاده می‌کند.

```bat
winget install -e --id Python.Python.3.12
```

(یا نصب دستی از <https://www.python.org/downloads/> — حتماً تیک
«Add python.exe to PATH» را بزنید.)

سپس در **Command Prompt**، داخل پوشه پروژه، این چهار خط را به‌ترتیب بزنید:

```bat
cd /d "مسیر پوشه پروژه"
py -3.12 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python run.py
```

> نصب کتابخانه‌ها بار اول چند دقیقه طول می‌کشد. اگر `.venv` قبلی با پایتون
> دیگری ساخته شده، `run.bat` خودش آن را بازسازی می‌کند؛ دستی هم می‌توانید
> `rmdir /s /q .venv` بزنید.

### ۲) دیدن پیام خطای واقعی

اگر `run.py` را دابل‌کلیک کرده‌اید، پنجره بسته می‌شود و خطا دیده نمی‌شود.
پس **همیشه از Command Prompt** (یا با دابل‌کلیک روی `run.bat`) اجرا کنید:

```bat
cd /d "مسیر پوشه پروژه"
.venv\Scripts\activate
python run.py
```

خطا در همان پنجره می‌ماند و در فایل `crash_log.txt` هم ذخیره می‌شود.

### ۳) اگر خطا مربوط به OpenGL بود

```bat
run_debug.bat
```

> از نسخه فعلی، خطاهای OpenGL (مثل `QOpenGLFunctions has no attribute
> 'GL_COLOR_BUFFER_BIT'` که در PySide6 رخ می‌داد) **خودکار** مدیریت می‌شوند:
> برنامه پس‌زمینه متحرک را به نسخه نرم‌افزاری سوییچ می‌کند و دیگر پیام خطای
> تکراری نشان نمی‌دهد. اگر نسخه قدیمی را دارید، `git pull` بزنید.

یا معادل دستی آن:

```bat
set SWIM_NO_GL=1
python run.py --no-gl
```

### 🎬 کنترل‌های پخش ویدیو

دکمه‌های پخش/مکث/توقف به شکل **گویِ شیشه‌ای براق** هستند — مطابق طرح مرجع
کاربر: رینگ نقره‌ای با ۴۴ ستارهٔ ریز، گوی آبی-بنفش با گرادیان عمودی
(تیره در بالا، روشن در پایین)، درخشش سفید پایین، بازتاب شیشه‌ای بالا و
سایهٔ نرم زیر دکمه؛ نماد سرمه‌ای با گوشه‌های گِرد. هر نماد در سه حالت
عادی/هوور/غیرفعال. پیش‌نمایش: `docs/media_controls_preview.png`

این تصویرها با `tools/make_media_buttons.py` ساخته می‌شوند و در
`app/assets/media/` ذخیره‌اند (اجرای برنامه به Pillow نیاز ندارد). برای تغییر
طرح، رنگ یا اندازهٔ گوی همین فایل را اجرا کنید تا تصویرها بازساخته شوند.

اگر روزی آیکون‌ها «مشکی و تخت» دیده شدند، علتش این بود که قالب SVG ویژگی
`color` را نداشت و شکل‌های `currentColor` به رنگ پیش‌فرض Qt (مشکی) رسم
می‌شدند؛ اکنون قالب همیشه `color="{color}"` را می‌نویسد.

### 🔤 متن‌ها چپ‌چین می‌شوند

دو دلیل فنی دارد و هر دو در نسخهٔ ۱.۱.۱ برطرف شده است:

۱. **تراز نسبی در Qt:** `AlignRight` در Qt نسبی است؛ در یک ویجتِ
   راست‌به‌چپ به «لبهٔ انتهایی» یعنی **چپ** ترجمه می‌شود. حالا تراز با
   `AlignAbsolute` اعمال می‌شود و همیشه یعنی سمت راستِ واقعی (فایل `app/rtl.py`).
۲. **جهت پاراگراف:** Qt جهت هر پاراگراف را از **اولین حرف** آن می‌گیرد؛ متن‌هایی
   که با کلمهٔ لاتین شروع می‌شوند (مثل «SWIM-AI برای …» یا
   «Front Crawl / Freestyle · …») چپ‌به‌راست چیده می‌شدند. حالا با نشانهٔ
   استاندارد یونیکد RLM درست می‌شوند (فایل `app/bidi.py`).

اگر باز هم جایی چپ دیدید، `selftest.bat` را اجرا کنید؛ بخش
«راست‌چین بودن متن‌ها» فهرست متن‌های مشکل‌دار را چاپ می‌کند.

### ⛔ برنامه در حین «تحلیل» بسته می‌شود (بدون پیام)

این علامتِ یک خطای سطح پایین (نیتیو) در MediaPipe یا OpenCV است؛ پایتون
فرصت چاپ Traceback پیدا نمی‌کند. سه گام:

1. **`run.bat` را دوباره دابل‌کلیک کنید.** از نسخهٔ ۱.۱.۰ خودِ لانچر بررسی
   می‌کند که OpenCV روی شاخهٔ 4 باشد؛ اگر نسخهٔ 5 نصب شده باشد (که MediaPipe
   را کرش می‌دهد) خودش تعمیرش می‌کند.
2. اگر پنجره اصلاً باز نشد یا بسته شد: **`selftest.bat`** را دابل‌کلیک کنید.
   یک آزمون گام‌به‌گام است و برای هر بخش (ساخت پنجره، صفحه‌ها، انیمیشن
   پس‌زمینه، پنجرهٔ «درباره»، راست‌چین بودن متن‌ها) `OK` یا `FAIL` می‌دهد.
   گزارش در `ui_selftest.log` ذخیره می‌شود.
3. اگر مشکل هنگام **تحلیل ویدیو** بود: **`diagnose.bat`** را دابل‌کلیک کنید. موتور تحلیل را
   بدون پنجره اجرا می‌کند.
   * اگر آن‌جا هم خطا/کرش داد → مشکل از MediaPipe/OpenCV است و متن خطا در
     `fatal.log` است.
   * اگر سالم تمام شد → مشکل از رابط کاربری/OpenGL است؛ با `run_debug.bat`
     (حالت امن، بدون OpenGL) اجرا کنید.
   * می‌توانید ویدیوی مشکل‌دار را روی `diagnose.bat` بکشید و رها کنید.
4. اجرای بعدی برنامه خودش تشخیص می‌دهد «دفعهٔ قبل وسط تحلیل بسته شد» و پنجره‌ای
   با **مرحلهٔ دقیق کرش** (استخراج اسکلت / محاسبات / رندر) و دکمهٔ «باز کردن
   پوشهٔ گزارش» نشان می‌دهد.

فایل‌های گزارش در پوشهٔ پروژه (یا `%LOCALAPPDATA%\SWIM-AI` در نسخهٔ نصب‌شده):

| فایل | محتوا |
|---|---|
| `fatal.log` | آخرین فریم‌های پایتون + آدرس خطای نیتیو (مهم‌ترین فایل) |
| `console.log` | همهٔ پیام‌های برنامه، Qt و PySide |
| `crash_log.txt` | Traceback خطاهای معمولی پایتون |
| `system_info.txt` | نسخهٔ پایتون، OpenCV، MediaPipe، Qt و … |

### ۴) صدا پخش نمی‌شود

- کلید 🔈 در نوار عنوان باید روشن باشد (تنظیم در رجیستری ذخیره می‌شود).
- صدای ویندوز/برنامه در «میکسر صدا» بررسی شود؛ پخش با `winsound` انجام می‌شود و
  به کارت صدای پیش‌فرض نیاز دارد.
- فایل صدا داخل برنامه است (`app/assets/startup.wav`)؛ نبود آن فقط بی‌صدایی
  می‌دهد و برنامه هرگز به‌خاطر صدا متوقف نمی‌شود.

### ۵) گزارش PDF ساخته نمی‌شود

- اول یک تحلیل را کامل کنید (دکمه‌های PDF تا آن موقع غیرفعال‌اند).
- اگر مسیر ذخیره دارای حروف فارسی/فاصله است، مشکلی نیست؛ ولی مسیر را در
  «دسکتاپ» یا «اسناد» انتخاب کنید.
- پیام خطای فارسی روی صفحه (نوتیف قرمز) و متن کامل در
  `%LOCALAPPDATA%\SWIM-AI\crash_log.txt` ثبت می‌شود.

### ۶) نکته‌ها

- برای اجرای دستی، **همیشه** اول `.venv\Scripts\activate` را بزنید؛ در غیر این
  صورت پایتونِ سیستم (همان ۳.۱۵) استفاده می‌شود و خطای `No module named 'PySide6'`
  می‌گیرید.
- روی لینوکس اگر `libEGL.so.1` خطا داد: `sudo apt-get install -y libegl1 libgl1 libglib2.0-0`

## نیازمندی‌های سیستمی

- Python 3.10 تا 3.14
- درایور گرافیک با پشتیبانی OpenGL 3.3 (در نبود آن، رندر نرم‌افزاری فعال می‌شود)
- فونت فارسی روی سیستم (مثل Vazirmatn / Tahoma) برای بهترین نمایش

### ⚠️ لینوکس: کتابخانه‌های GL/EGL برای MediaPipe

مدیاپایپ نسخه ۱.x حتی برای استنتاج روی **CPU** به کتابخانه‌های GL/EGL لینک شده است؛
اگر نصب باشند ولی این کتابخانه‌ها نباشند، برنامه با پیام
`libEGL.so.1: cannot open shared object file` متوقف می‌شود. پیش از اجرا:

```bash
sudo apt-get install -y libegl1 libgl1 libglib2.0-0
```

(نسخه‌های دسکتاپ ویندوز معمولاً به نصب دستی نیاز ندارند.) برنامه در صورت بروز این
خطا پیام راهنمای فارسی/فینگلیش نشان می‌دهد.

### 📁 نام فایل‌های فارسی

OpenCV روی ویندوز مسیرهای غیرلاتین را باز نمی‌کند؛ SWIM-AI در این حالت ویدیو را
به‌صورت خودکار به یک کپی موقت با نام لاتین منتقل می‌کند و خروجی را در پایان به نام
اصلی برمی‌گرداند. پس ویدیوی `شنا.mp4` و خروجی `تحلیل.mp4` هر دو کار می‌کنند.

## مدل‌های تشخیص اسکلت

پوشه `models/` شامل باندل‌های آماده MediaPipe PoseLandmarker است
(`pose_landmarker_lite.task` و `pose_landmarker_full.task`). اگر این فایل‌ها
موجود نباشند، برنامه در نخستین اجرا تلاش می‌کند مدل را دانلود کند؛ می‌توانید با
متغیر محیطی `SWIM_POSE_MODEL` مسیر مدل دلخواه را هم مشخص کنید.

## نکته دقت

صحت نتایج به زاویه دوربین (ترجیحاً نمای پهلو و ثابت در ارتفاع لگن)، نور
یکنواخت و کیفیت ویدیو وابسته است.

- **کالیبراسیون سرعت** بر اساس نسبت‌های آنتروپومتریک (Winter, 2009) و در صورت
  نیاز با `--height` / `--meters-per-pixel` انجام می‌شود. مؤلفه عمودی حرکت
  (بالا و پایین رفتن شناگر) در محاسبه سرعت حذف می‌شود تا نوسان کمر سرعت را
  بیش‌برآورد نکند.
- **SPM** بر پایه فاصله میانه دو ضربه پیوسته محاسبه می‌شود و برای کلیپ‌های کوتاه
  که فقط یک ضربه دارند، از تخمین فرکانس تناوبی استفاده می‌شود.
- **SWOLF** با طول استخر داده‌شده (`--pool-length`، پیش‌فرض ۲۵ متر) نرمال می‌شود؛
  برای مقایسه جلسات، همیشه همان طول استخر و همان زاویه دوربین را نگه دارید.

## تست‌ها و اعتبارسنجی

موتور تحلیل مستقل از MediaPipe و رابط کاربری تست می‌شود؛ یک شناگر مصنوعی با
سینماتیک معلوم (طول استخوان‌های واقعی، مسیر دست، دوربین سوراخ‌سوزنی) ساخته
می‌شود و خروجی‌های سبک/SPM/سرعت/SWOLF با مقدار زمینی مقایسه می‌شوند:

```bash
pip install -r requirements-dev.txt
pytest
```

پوشش تست‌ها: صحت سبک و نرخ ضربه، حذف نوسان عمودی از سرعت، لغو تحلیل، رندر ویدیو
(شامل مسیرهای فارسی)، خروجی JSON، گزارش متنی و پایداری موتور پیشنهادها در برابر
داده‌های NaN.
